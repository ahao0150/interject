# MiniMind 异步感知注入实验报告

2026-11-01 · Windows 11 + RTX 3060 12GB + 64GB RAM · 只用 MiniMind（64M，`minimind-3`）

## 一句话结论

**机制成立，效果受限。** 「不阻塞生成、在中途插入外部感知、并让后续推理轨迹改变」这条链路在 64M 上完全跑通，
非阻塞确实比阻塞等待省时间（省 0.22 s / 每次，与等待量同量级）；
但「模型真的理解了注入信息并据此改变答案」这一层，64M 撑不起来——相关感知的采纳率没提升，反而略降。
瓶颈在模型能力，不在框架。

## 一、假设

一个正在生成思考链的模型，如果能**不中断**地接收后台感知片段（传感器、别的程序、用户新输入），
它会比「停下来等外部反馈」更快，并且能据此改变后续推理。

拆成四个可验证子命题：

1. 非阻塞中途注入在技术上可实现，且不 OOM；
2. 注入会改变后续推理轨迹（不是被忽略）；
3. 非阻塞比阻塞省端到端时间；
4. 模型能学会「采纳相关感知、忽略无关噪音」。

## 二、方法

### 2.1 关键实现

MiniMind-3 的 `config.json` 走 **transformers 原生 Qwen3 实现**（`modeling_qwen3.py`），不是仓库里的
`model/model_minimind.py`。这一点决定了实现方式：用标准 `DynamicCache`，用 `get_seq_length()` 取已缓存长度。

注入方式：在自写的逐 token 解码循环里，当感知到达时，把
`\n[PERCEPTION]…[/PERCEPTION]\n` 编码后**追加到 `input_ids` 尾部**，
下一轮 forward 只处理 `input_ids[:, past_len:]`，注入的 token 自然并入 KV cache。
**不需要重算前缀**，这就是「真·非阻塞」。

三种模式：

| 模式 | 行为 |
|---|---|
| `none` | 不注入（对照） |
| `blocking` | 到第 N 步暂停，等感知可用，插入后继续 |
| `async` | 不停顿，感知到达那一刻插入，继续生成 |

代码：`minimind/asinject/inject.py`（约 200 行）。

### 2.2 修掉的两个真实 bug（否则实验无效）

1. **KV cache 长度取错**：`past_key_values[0][0].shape[1]` 在 `DynamicCache` 上取到的是 **kv_heads 数（4）**，
   不是序列长度，导致只喂 18/22 个 token，输出全是乱码。改用 `get_seq_length()`。
   顺带发现官方 `generate` 因为没有正确处理 cache，**每步都在重算整个前缀**。
2. **训练样本丢失注入内容**：`raw_text` 只解码生成的 token，注入的 token 直接进了 `input_ids` 不在其中。
   改为按 token 序列重建完整文本。

## 三、结果

### 3.1 阶段 0：基线（无注入）

20 条固定 prompt，`seed=1234+i`，`max_new_tokens=128`：

- 20/20 完成，无 OOM
- 平均 **45.38 tok/s**，显存峰值 **0.131 GB**
- 首条 20.4 tok/s（预热），其余 37.6–52.4 tok/s

### 3.2 阶段 1：注入 demo（2 个案例 × 3 模式）

相关感知 = 「用户是素食者，不吃任何肉类。」

| 模式 | 生成 | 耗时 | 等待 | 注入点 | 轨迹漂移 | 采纳 |
|---|---|---|---|---|---|---|
| none | 128 tok | 2.90 s | 0 | — | 0 | ✗ |
| blocking | 128 tok | 3.29 s | 0.69 s | 第 5 token | 0.877 | ✓ |
| async | 128 tok | **2.64 s** | **0** | 第 38 token | 0.631 | ✓ |

**非阻塞省 0.65 s，约等于阻塞等待量（0.69 s）**，两个模式都采纳了「素食」。

噪音案例（「窗外温度 26 摄氏度」）：两种模式都没采纳 ✓，但 async 输出里出现了
`[PERCEPTION] [/AKER] [/AKER]` 的**标记复读残渣**——这是 64M 的模仿行为，阶段 2 的数据要治它。

### 3.3 阶段 2：数据与训练

- 训练数据 **478 条**（从 547 条候选中丢弃 69 条退化样本），由 **MiniMind 自己生成**，未使用任何外部模型
- 五类主题 × 三类感知（relevant / conflict / noise），感知与问题同主题匹配
- 注入点固定在第 24 token，感知以 `[PERCEPTION]…[/PERCEPTION]` 包裹
- LoRA rank 16 → **0.393M 参数（0.61%）**
- 2 epoch / 240 step / **83 秒**，loss 1.96 → 1.31，无 OOM，未触发任何降级

### 3.4 阶段 3：四组对照（30 条 prompt，seed 777）

| 组 | 可读性代理 | 平均耗时 | tok/s | 轨迹漂移 | 采纳率 | 噪音泄漏 |
|---|---|---|---|---|---|---|
| A 基线·无注入 | 0.987 | 2.143 s | 44.14 | 0 | 0.100 | 0.067 |
| B 基线·阻塞注入 | 0.957 | 2.477 s | 38.10 | 0.630 | 0.133 | 0.067 |
| C 微调·无注入 | 0.973 | 2.204 s | 43.79 | 0.585 | 0.133 | 0.067 |
| D 微调·非阻塞注入 | **0.980** | 2.259 s | 42.72 | 0.645 | 0.067 | 0.067 |

## 五、第 1 条为什么没过（失败分析）

不是框架问题。为了把「注入时机」和「微调效果」这两个变量分开，额外跑了一组**对齐注入点**的对照
（`asinject/eval_aligned.py`，`reports/eval_aligned.json`）：两组都强制在第 20 token 注入、感知视为已到达、
无等待，差别只剩「是否微调」。

| 组 | 注入点均值 | 采纳 | 复读标记 | 可读性 | 相对 B0 漂移 |
|---|---|---|---|---|---|
| B0 基线·固定注入 | 20.0 | **4/30 (0.133)** | 1/30 | 0.957 | 0 |
| D0 微调·固定注入 | 20.0 | **4/30 (0.133)** | 1/30 | 0.947 | 0.673 |

**结论很明确：注入点对齐后，微调前后的采纳率完全相同（4/30），复读标记也一样（1/30）。**

于是三条原因可以按权重排序：

1. **注入点太晚是主因**。主实验里 B 在第 20 token 注入，D（async）在第 38–39 token 注入，
   留给「被感知影响」的空间少了一半以上。这正是非阻塞的固有代价——它用更晚的注入点换来了不等待。
   对齐后 D0 立刻回到 13.3%，与 B 持平。
2. **微调没有教会「采纳」**。同样注入条件下，240 步/478 条的 LoRA 让输出分布明显变了（漂移 0.673），
   但采纳率一个点都没涨，可读性还略降（0.957 → 0.947）。也就是说它学到的是「像这样说话的风格」，
   不是「遇到感知就这么处理的能力」。数据量、步数、模型容量三者都不够。
3. **指标本身失效**。采纳率用「关键词是否出现」判断，模型完全可能理解了却不复述关键词。
   抽检 D 组证实：内容连贯、结构清晰，只是没出现「30 分钟」这几个字。这个指标测的是复述，不是采纳。

另外更正一处主实验的观察：标记复读（`[PERCEPTION]` 残渣）在对齐实验里只有 **1/30（3.3%）**，
属于偶发退化，不是系统性问题，不必当作主要缺陷。

## 六、哪些结论可信

**可信（有直接测量支撑）**：

- 非阻塞中途注入在 64M 上可运行、不 OOM，注入确实改变后续轨迹（漂移 0.63–0.67，远高于 0）
- 非阻塞相对阻塞省下的时间 ≈ 被省掉的等待时间（0.218 s vs 0.349 s，同量级）
- 噪音忽略能力天然具备（93.3%），无需训练即成立
- **注入点位置是效果的第一决定因素**：同一模型、同一感知，第 20 token 注入得 4/30，
  第 38 token 注入只得 2/30——这一条有对齐实验直接支撑
- **这次 LoRA 没有提升「采纳」能力**：对齐注入点后 4/30 vs 4/30，完全持平（这是负面结论，但证据最硬）

**不可信 / 受限于实验规模**：

- 「模型学会采纳相关感知」——**未证实**。指标失效 + 模型太小 + 数据自举，三重限制下无法下结论
- 所有效果量都来自 478 条自举数据、240 步训练、30 条评测，**统计功效很低**，不能外推到更大模型或更多数据
- 训练数据由 64M 自己生成，**教师和学生是同一个模型**，数据质量上限就是模型能力上限
- 可读性是**自动代理指标**（长度/去重/垃圾标记/中文占比），不是人工评分
- 主实验里 D 组可读性最高（0.980），但对齐实验里微调后反而略低（0.947 vs 0.957），
  说明可读性差异在噪声范围内，不宜单独作为论据

## 七、下一步建议

按性价比排序：

1. **先修测量，再谈效果**。把采纳率换成人工抽检 30 条（或换更大的模型当裁判——但那违反本项目约束，
   需要你先放开限制）。现在的指标不配用来判断成败。
2. **把注入点对齐**再比一次：让 async 也固定在某个 token 位置注入（感知提前到达），
   这样才能分离「模式差异」和「注入时机差异」这两个变量。
3. **加长生成**（256–512 token），让注入后还有足够空间产生影响；96 token 里减去注入点只剩余 50 多个。
4. **治标记复读**：数据里加入「看到标记后不复述标记」的负样本，或用更自然的注入措辞（如中文括号）。
5. 若要验证「异步感知」的真实价值，**换 200M–1B 量级**才能看出理解层效果；
   64M 只适合验证机制，不适合验证能力。
